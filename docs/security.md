# 权限与本机通信

应用声明 `INTERNET` 和 `MODIFY_AUDIO_SETTINGS`：前者用于连接电视自身的 ADB 和本机辅助进程，这两条连接限制在 `127.0.0.1`；后者用于音频焦点与电视音量/HDMI 硬件静音同步。可选配对配置启用后，shell 辅助程序还会连接用户明确指定的 Apple TV：Companion 用于细步进，AirPlay/MRP 用于观察输出路由。没有遥测、Apple 账号登录或云端服务。

Android 端不主动扫描局域网。电脑配对脚本只对 `--host` 指定的 Apple TV 地址做定向服务发现和配对；安装脚本只连接 `--serial` 指定的电视。配对授权与应用/辅助程序 HMAC 是不同身份，不可互换。

## 权限边界

Android 应用本身不能独占原始遥控器输入。用户在电视上开启 ADB 并允许应用生成的
ADB 公钥后，应用通过本机 ADB 以 `shell` 身份启动辅助进程。它会独占匹配的
遥控器设备、转发音量键，并重新注入其他已映射按键。因此，ADB 授权赋予的能力
高于普通应用权限，应只安装自己信任或审阅过的构建。

项目不获取 root，不修改系统分区、系统 APK 或固件，也不自动更改 ADB 开关。
电视固件开启 ADB 后是否同时对局域网开放调试端口，由固件决定。
不使用时可以停止辅助进程并关闭 ADB。

## 认证与密钥

- Android ADB 的 RSA 私钥在应用 `noBackupFilesDir` 内本机生成，保留重启后的授权身份。
- 音量桥在应用私有、不参与备份的目录保存 32 字节随机 `bridge-v4.key`。升级到 alpha.4 会生成新身份，不复用或接受 v3 密钥/协议。
- ADB 只传送 helper 代码和启动参数，不传送桥密钥。旧版直接通过 ADB SYNC 传密钥的方式已删除；单凭占用本机 5555 端口并模拟 ADB 的普通应用不再能接收此密钥。
- 应用在启动 helper 前创建随机命名的 abstract Unix socket，最多保留 30 秒。应用读取操作系统提供的 peer credentials，仅接受 UID `2000` 的 shell 进程，在校验通过前不发送密钥；接受连接后的握手也有超时。
- helper 要求自身为 shell UID，并核对 Unix socket 对端 UID 等于启动参数中的应用 UID；不匹配时不读取密钥。应用 UID 来自实际启动命令，名称和 UID 是公开参数，不是秘密。此流程依赖 Android 的内核 peer-UID 保证；尚未在目标固件验证。
- helper 只在内存持有桥密钥，不再写入 shell 密钥文件；安装/卸载会清理旧版 `cec-bridge-v3.key` 及其临时文件。
- 密钥不放进命令行、日志或后续 TCP 握手。协议 v4 使用双方随机 nonce、区分角色的 HMAC-SHA256 和常量时间比较进行双向认证，完成后才处理状态与音量命令。
- 认证后的命令没有逐条 MAC 或加密，依赖本机 TCP 连接的边界。它不适用于远程网络通信。

这能限制普通本机应用冒充辅助进程或服务器；它不防御 root、已有 ADB/shell 权限的程序、
恶意固件或本机端口拒绝服务。源码中的配置与协议常量都不是秘密。

## 释放与删除

应用离开前台后辅助进程释放输入设备；连接失败也会释放。辅助进程另有看门狗，
在抓取输入但连续约 3.5 秒未推进时，先停止接收新的按键记录、原子领取尚未释放的按键，再在最多 250 毫秒的清理窗口内尽力发送对应 UP，随后强制退出。正常松手、断线清理和看门狗共用领取逻辑，避免同一记录重复释放。各 UP 在独立 daemon 线程尝试，单个注入阻塞不会阻止其他按键的尝试或进程退出。若系统已阻塞于 DOWN/UP 注入，无法保证逻辑按住状态完全恢复；进程退出仍由系统关闭 evdev 句柄。
这些是源码中的保护机制，Alpha 版仍需要实机验证边界情况。

按电视主页键只离开转发界面，后台信号源观察器仍可运行。要完全停止，使用
`scripts/device.py --serial TV_IP:5555 stop`；重新打开应用会再次启动辅助进程。
完整卸载使用该脚本的 `uninstall`，同时移除已知的 shell 辅助文件、桥密钥和公开 Alpha 的电视侧配对配置。
只从电视设置卸载 APK 不会自动清理 `/data/local/tmp` 中的这些文件。

构建用的 debug 签名密钥只生成在忽略的 `build/` 中；发布前应另行建立并妥善保管
正式签名密钥。不要提交私钥、个人调试授权文件、原始设备日志或家庭照片。
报告问题时请先删除日志中的设备标识和个人内容。

## Apple TV 配对身份

用户在自己的电脑运行可选 `pyatv==0.18.0` 完成 PIN 配对。脚本把配置写入用户所有的 `0700` 目录，文件独占创建为 `0600`，不会覆盖现有身份，不把凭据打印到终端。`.private/`、常见配置/身份文件和虚拟环境被 Git 忽略。忽略规则不是数据脱敏器，不要使用强制添加或把真实配置改名提交。

通过明确授权的电视 ADB，把配置从标准输入传给 shell，保存到 `/data/local/tmp/cec-bridge-private/companion.conf`。目录必须由 shell 拥有并为 `0700`，文件必须是 shell 所有的普通文件且为 `0600`，拒绝符号链接。helper 缺少有效配置时停用网络精调，基础 CEC 可继续工作。新路径与私有原型的路径独立。

Companion/AirPlay 会话使用配对加密身份；私有字段包含设备地址、输出名称和长期密钥，均不可公开。默认可复用 Companion 凭据观察 AirPlay 路由；也允许单独提供 AirPlay 凭据。严格配置权限不能防御 root、其他 ADB/shell 授权者或恶意固件。公开版新配对和路由适配尚未实机验证，也未经外部安全审计。

耳机身份只接受明确配置的完整名称。未知、多输出、过期路由不推定为耳机。alpha.4 为路由快照记录输出名称及可用的设备/组标识；身份变化或状态失效会废弃旧队列和进行中的音量读取基线，并在提交绝对音量写入前再次核对。设备端没有“核验路由并同时写音量”的原子接口，远端仍可能在最后检查后切换输出，因此不能承诺彻底消除这类竞态。失败或结果不确定的精调不会自动重写或转走 CEC。

配对校验消息、TLV 分片/字段、OPACK 节点与引用数量都有上限。网络命令、HTTP 读取和握手使用整次操作的单调时限，截止时关闭 socket，覆盖持续分段响应及阻塞写入，而不是只依赖单次读取空闲超时。实际电视的网络延迟和恢复行为尚待回归。详见[配对与失败行为](pairing.md)。

`stop` 保留身份，`uninstall` 删除本项目公开 Alpha 的电视侧配置。电脑私有文件和 Apple TV 已授权身份需要用户单独删除/撤销；仅卸载 APK 不等于撤销网络配对。

## 息屏联动

公开构建默认关闭。开启后使用现有 shell 权限读取系统状态、注入电源键，以及临时写入 `hdmi_control_auto_device_off_enabled`。仅向 `android` 包发送已核验固件的 `mitv.goto.str_mode`，不广播 ACTION_SHUTDOWN，不修改系统分区。原厂 Standby 是 CEC 广播，可能影响其他 HDMI 设备。标记文件用于恢复被中断的设置，stop/uninstall 在停止进程后尝试还原。杀进程到再次恢复之间仍可能存在临时设置未还原的窗口；此机制不是事务级原子保证。

界面记忆只保存在辅助进程内存，重启丢失后不强制全屏。每次状态响应在认证连接内携带三个功能开关；应用退出后已启用的联动继续运行。要完全停止请使用 stop 命令。
